# Shadow Tower

Binary-matching decompilation of Shadow Tower for the PlayStation, North American
release `SLUS-00863`.

Original project contributions are dedicated to the public domain under
[CC0 1.0 Universal](LICENSE), to the extent of the contributors' rights.
This does not grant rights to FromSoftware's game or Sony/Psy-Q material.
No game data is included: supply your own disc image. The Nix environment
downloads Sony's Runtime Library 4.2 and the Psy-Q 4.x tools separately; see
[the toolchain documentation](docs/toolchain.md).

The disc carries seven linked programs and 36 code overlays, 43 images in
all. `PSX.EXE` (the boot file `SLUS_008.63`; the disc also holds an
identical `PSX.EXE`) is a program sequencer: its table names, by index,
`STR.EXE`, `TITLE.EXE`, `OPTXT.EXE`, `ST.EXE`, `END.EXE` and `VS.EXE`. It
runs index 0 (`STR.EXE`) first, then after each program returns it loads
the index that program left in the byte at `0x800103F0`. `STR.EXE` (the
boot movies) hands over to `TITLE.EXE`. `TITLE.EXE` picks `OPTXT.EXE` (the
opening text) for a new game, `ST.EXE` for Continue (also writing 2 to the
mailbox byte `0x800103F1`), `VS.EXE` for versus, and `STR.EXE` again when the
title screen times out. `OPTXT.EXE` hands over to `ST.EXE`, `ST.EXE` to
`END.EXE`, and `END.EXE` and `VS.EXE` back to `TITLE.EXE`. All programs but
`TITLE.EXE` (`0x80012000`) load at `0x80011000`.

| Image | Disc file | Load address | Load size |
| :---- | :-------- | -----------: | --------: |
| `PSX.EXE` | `SLUS_008.63` | `0x80010000` | `0x800` |
| `STR.EXE` | `STR.EXE` | `0x80011000` | `0x22000` |
| `ST.EXE` | `ST.EXE` | `0x80011000` | `0x77800` |
| `TITLE.EXE` | `TITLE.EXE` | `0x80012000` | `0x17000` |
| `OPTXT.EXE` | `OPTXT.EXE` | `0x80011000` | `0xe800` |
| `VS.EXE` | `VS.EXE` | `0x80011000` | `0x52800` |
| `END.EXE` | `END.EXE` | `0x80011000` | `0x1f000` |
| `FDAT_nnn.BIN` (36) | `ST\COM\FDAT.T` entry *nnn* | `0x801EB560` | `0x2800`–`0x4800` |

`ST.EXE` loads one headerless code overlay at a time from `ST\COM\FDAT.T`
(entries 2, 12, ..., 472; the other entries are data) at `0x801EB560`, the
end of its own `.bss`. The overlays share `ST.EXE`'s address space and call
straight into its code, and each starts with an id word and 32 handler
pointers. They are named by archive entry (`--image fdat_012`) because the
map each one belongs to is not yet proven; entries 2, 322 and 402 are
byte-identical. `config/images.toml` records every hash and layout.

## Getting started

```sh
nix develop
kf extract --disc /path/to/ShadowTower.cue   # checks the disc hash, writes retail/
kf init --retail-dir retail
kf build
kf status
```

`config/images.toml` records the disc, executable, archive and overlay
hashes. `kf extract` refuses any other dump; it copies the programs and
`FDAT.T` and slices the overlays out of it (`kf init` re-derives missing
overlay files from `retail/FDAT.T`).

The tooling and matching workflow come from the King's Field II
(`SLPS-00069`) project, which builds on the King's Field (`SLPS-00017`)
project. The toolchain and link model are Shadow Tower's own: the SN Systems
GCC 2.7.2 compiler (a rebuild), the DOS builds ASPSX 2.79D, DMPSX 3.0,
PSYLINK 2.73D and CPE2X 1.5, and Runtime Library 4.2, which rebuild `PSX.EXE`
byte-identical. See [AGENTS.md](AGENTS.md) for the reconstruction rules.
